# The build pattern — how a slide is rebuilt in this deck

**SDS's rule, stated three times before it landed (2026-08-31):**

> *"I want you to parse out the individual components from this visual diagram… build them up
> sequentially… as each component appears the box that explains that particular component appears as
> well. And when I click next, the next visual element appears, and simultaneously the box of the
> first element disappears… positioned strategically so that as much of the overall slide is still
> visible."*

Two things I got wrong twice before this, so they are worth stating as prohibitions:

- 🟥 **Do NOT redraw the picture as abstract boxes and build THOSE.** The first 'omics rebuild
  replaced a real diagram (chromosomes, a helix, proteins, a living cell) with four stacked
  rectangles labelled Genome / Proteome / Cells. It built up correctly and it was still the wrong
  thing: the audience lost the picture. **Take the original apart; do not paraphrase it.**
- 🟥 **Do NOT put the explanations in a column that accumulates.** One box, on screen only while its
  own component is the current one, and gone the moment the next arrives.

## Three routes to the components, in order of preference

| Route | When | Example |
|---|---|---|
| **1 · Recover the original build layers** | the figure was generated by a script that already emits stages | `img/d2l/*` — 18 transparent stages recovered from `StratBase/Proposals/Geomics/media/figures/_layers/`, generator `geomics_darkness_to_light_260708.py` |
| **2 · Cut a flat render apart** | only a finished PNG survives | `img/omics/*` — cut from `img/orig/gt2025_omics-13.png` by `tools/decompose_figure.py` |
| **3 · Draw it** | no original exists, or the original is a wall of text | `Same organ, different disease` — inline SVG with `<g class="lg lgN">` groups |

**Always try route 1 first.** On 2026-08-31 the darkness-to-light figure looked like route 2 work
until a search turned up a `_layers/` folder that had done the job in July.

## Route 2: `tools/decompose_figure.py`

Cutting a flat PNG apart is not "crop some rectangles". Rectangles cut through neighbouring art and
leave visible seams against the slide background. What works:

1. **Fit the background, do not guess it.** A degree-5 polynomial surface over the ~74% of pixels
   that are background. On the 'omics render the median residual was **0.58/255**, p99 **4.4** — so
   a component pasted back onto the plate is invisible at its own edges.
2. **Foreground = `|pixel − plate| ≥ 10`**, then connected-component labelling.
3. **Assign each BLOB whole**, to whichever component's rectangles hold ≥80% of it. Rectangles are
   how you *address* components, never how you cut them.
4. **Split only the blobs that genuinely merge.** On the 'omics figure exactly three did: the
   chromosome/coil/helix ribbon, the machine + arrow + living cell, and one arrowhead touching a
   chromosome arm — that last one split by colour, not geometry.
5. **Check the residue.** 99.98% of foreground assigned, and stacking every layer reproduced the
   original to a mean **0.63/255** per pixel. If that number is not near zero, the cut is wrong.

## The HTML grammar

One `data-frag` element per click, holding *both* the picture part and its box, so they arrive
together:

```html
<section class="slide obuild" data-t="…" data-sid="…" data-n="…">
  <div class="ob-pic">
    <img class="ob-plate" src="img/…/plate.png" alt="">
    <div class="ob-step" data-frag="1">
      <img src="img/…/dna.png" alt="DNA">
      <div class="ob-note" style="--x:52%;--y:14%;--w:44%">
        <div class="k">DNA</div><div class="d">…</div>
      </div>
    </div>
    …
    <div class="ob-step" data-frag="1"><div class="ob-scrim"></div>
      <div class="ob-note wide" style="…">…</div></div>
  </div>
</section>
```

- `data-frag` values are **ignored** — `setFrags()` walks the NodeList in document order, so one
  `.ob-step` = one click.
- Only one box shows, via CSS alone: `.ob-step:has(~ .ob-step.shown) .ob-note{opacity:0;visibility:hidden}`.
- For an **SVG** picture, the step holds only the box and lights its group:
  `.lungb:has(.ob-step.l3.shown) svg .lg3{opacity:1}`.
- `.ob-scrim` dims the finished picture for a closing card. It buys **legibility, not coverage** —
  the box still hides whatever is under it.

## Box placement is measured, not eyeballed

The box goes where the art *already revealed* is not — and "already revealed" is the whole point:
a later component can be sat on, because it is not on screen yet.

```
python3 tools/verify_build.py --sid 04c7c6 --manifest img/omics/manifest.json \
        --allow "8:protein,8:dna,8:machine" --shots /tmp/omics
```

Per step and per viewport width (1280/1366/1600 by default) it reports anything escaping the slide,
any image that failed to load, and the overlap between the current box and every component revealed
so far. `--allow STEP:COMPONENT` **declares** a deliberate collision rather than silencing the check.

**The honest limit of the pattern:** on the last step of a dense figure the picture is full and the
box must sit on something. Put it on the least information-dense thing already explained, and say so.
On the 'omics slide that is the proteins and the arrow at step 8 — the only declared exception in
the deck.
